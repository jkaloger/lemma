In: unpinned refs, immutable claims, checks 1–4, `check`, `apply`, `refs`, `stop`, `signal` (PostToolUse), context pointers, once-per-session dedupe, `migrate`, base resolution for branches and trunk-only repos, pack hooks as composition, skills, README, CI template. Lemma uses the lazyspec 0.15 extractors as they are.

48. **Refs are unpinned.** A receipt is an `@ref` line naming `<path>#<symbol>`. A pinned form (`@<sha>`, `@{blob:…}`) or ` [forced]` is an error: `pinned ref; run lemma migrate`. `@base` lines are an error with the same hint.
49. **`@checked` goes.** A claim no test settles is `[intent]`. Human judgement of adequacy happens at `complete`, not in a line. `migrate` turns a claim whose only receipts are `@checked` into `[intent]`.
50. **Claims are immutable.** A delta claim whose id exists in the target spec is an error unless struck: `claims are immutable; strike <id> and add a new id`. Fold appends new ids and deletes struck ids. A struck id the spec lacks is an error at `apply` and in `check` (check 4). Two in-flight deltas striking one id is a warning.
51. **The four checks.**
    1. Coverage: when the range's changed governed files span more than one spec's `governs`, each touched spec that no in-flight delta (draft or in-progress) folds into, and no delta that became `complete` in the range folds into, is an error. A delta became complete in the range when its `index.md` changed in the range and its status at the base was not `complete` (or it did not exist at the base). One area alone needs no delta (chores stay free). Amends DECISION-001 check 1.
    2. Evidence: for each claim present in a spec's `behaviour` part at the base, each `@ref` region whose extracted, normalised text differs between base and working tree is an error unless a delta strikes that claim. A region absent at base is not a change; changed means present at base and now absent or different. Only a delta that folds into the claim's spec, strikes in that spec's `behaviour.<spec-id>` part, and is in-progress or became complete in the range counts; a draft delta does not. `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs` and `.cjs` use the TypeScript extractor and grammar. Files with no extractor compare whole.
    3. Claims have evidence: every live, non-`[intent]` claim has at least one `@ref` that resolves to a symbol in a file matching the governing spec's `tests` globs.
    4. Integrity: decision 50, plus the 1.5 structural findings kept (fold targets resolve, parts name targets, no claim in `index.md`, invalid globs), plus two range rules. A spec whose `behaviour` part differs from the base must equal the base claims folded (id order) with every delta that became complete in the range, compared as claim id and first-line text with `[intent]` ignored; otherwise error `spec behaviour edited outside a fold; change it through a delta` on the spec part. A change in the range to a spec's `governs` or `tests` is a warning `governs/tests changed in this range; review`. A spec absent at the base is not compared.
52. **Base resolution.** `--base <rev>` wins. Else, with the trunk (`--trunk <name>`; default `main` if it exists, else `master`, else the target of `origin/HEAD`, else none), if `merge-base HEAD main` is not HEAD, use it. Else HEAD is on trunk (direct-to-main): Stop and `signal` use the session base; the gate (payload with a transition) uses the parent of the commit that first added the moved delta's `index.md`, or HEAD when the delta is uncommitted; the validate event uses no base. Else HEAD. CI passes `--base` explicitly: the PR base ref, or the push's `before` sha (fetched, tolerating failure, falling back to `--trunk origin/<default-branch>` after a force-push). A new-branch push passes `--trunk origin/<default-branch>`.
53. **`lemma check`.** Runs checks 1–4. Severity: invariants (2, 4, refs that do not resolve, pinned refs) are errors; a claim without evidence (3) is a warning unless required. `--require <claims|evidence|clean>` (repeatable) turns readiness into errors: `claims` = Intent present, every fold target has its part, at least one claim; `evidence` = check 3 errors; `clean` = no uncommitted changes in ref files or under a target's `governs`. Output is `path:line: severity: message` lines, silent when clean, exit 2 on error. `--json` prints `{"findings": […]}`. `--hook` reads a lazyspec payload on stdin, prints findings JSON, exits 0, scoped to the payload documents. The `validate` event (no transition) skips checks 1 and 2 and the spec-edit rule (CI runs `lemma check --base`). A pre-transition gate runs them against the range and limits their findings to the moved delta's target specs.
54. **Transitions are config.** The pack's `[[hooks]]`: `check --hook` on validate; `check --hook --require claims` on draft→in-progress; `check --hook --require evidence --require clean` then `apply` on in-progress→complete. Lazyspec runs them in order and stops at the first error, so `apply` never writes after a failed check. `lemma pre-transition` and `lemma validate` go.
55. **`lemma apply`.** With no argument it is the pre-transition hook: reads the payload, folds each target, returns `updates`; errors on check 4 and on a target with no `behaviour` part; warns for a draft target. `lemma apply <delta>` previews: prints per target the ids it would add and delete, writes nothing.
56. **`lemma refs <claim>`.** Prints `<claim> <path>#<symbol> ok|unresolved|not-a-test` per ref, across specs and in-flight deltas.
57. **`lemma stop`.** Claude Code Stop adapter: checks 1–3 against the session base (decision 52), with check 3 scoped to session-touched documents (spec and delta files changed in the range, and specs whose `governs` cover a touched file), plus a completion rule: a delta `complete` in the working tree that was not `complete` at the session base (HEAD when no base is recorded) is an error, including one completed and committed in the session. It is said once per session through the `.said` file, so only the first Stop after a human completes a delta is blocked. Exit 2 with diagnostics on stderr on error. `stop_hook_active` exits 0. Pending-test detection goes.
58. **`lemma signal`.** Claude Code PostToolUse adapter for Edit, Write and MultiEdit. Scoped to the touched file: context pointers on the first touch of a governed area in the session (one line: `<path> → SPEC-003 store · DECISION-004 …`, from `governing()` and `affects` links, no content); check 2 for refs into the file; check 1 if the file adds an uncovered area; check 3 and 4 when the file is a spec or delta part. Output goes back to the agent as `additionalContext`; never blocks. Each message is said once per session, keyed on a stable identity (`context:<ids>`, `check1:<spec-id>`, `check2:<claim>:<path>#<symbol>`, `check4:<doc>:<path>:<message>`) rather than rendered text; hashes kept in `<git-dir>/lemma/sessions/<id>.said`. The base is resolved only when the file is governed, referenced or a spec or delta file; no `lazyspec --version` spawn. For a spec file, the check 4 spec-edit rule and `governs`/`tests` warning are included.
59. **`lemma migrate`.** Rewrites every spec and delta part in place: strips the pin and ` [forced]` from `@ref` lines, deletes `@base` lines, applies decision 49. Prints the files it wrote. A delta claim with an `@base` line whose id exists in its target spec (a replacement) becomes a strike of the old id plus the claim under `<old-id>-R` (`-R2`, `-R3` if taken); each rewrite prints an indented line under the file. Idempotent.
60. **Removed.** `re-pin`, `receipt`, `base`, `validate`, `pre-transition`; receipt freshness, symbol drift, `[forced]`, `@checked`, `@base`, pending-test detection. `session-start` stays.
