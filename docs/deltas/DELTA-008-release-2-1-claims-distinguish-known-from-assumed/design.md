64. **Review surface.** `lemma apply <delta>` preview, and the `in-progress → complete` gate findings in `--hook` mode, print per target: `New commitments`, `Observed behaviour`, `Resolved assumptions`, `Discarded assumptions`, `Unresolved assumptions`. Resolution is derived from the range's commits, not the base: the union of ids that were `[assumed]` in any committed version of the claims part within the range (`git log -p` on the part), minus those `[assumed]` now, is resolved; an id in that union that is gone is discarded. A resolved id kept in place prints `AC-17: was assumed, now a commitment`; one replaced prints `A-1 → AC-17`; a replacement is recognised only when, in one step through the versions (the working tree counts as the last), exactly one assumed id vanished and exactly one new id appeared with overlapping claim text (Jaccard of lowercase words at least 0.5), otherwise the assumption is discarded, so a dropped assumption is never shown as resolved. In `--hook` mode the surface is one finding per claim (`AC-17: new commitment; provenance: none; accepting this delta establishes this behaviour`), warning severity, emitted at the `in-progress → complete` gate only.
